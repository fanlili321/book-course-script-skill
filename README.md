# book-course-script

根据螺丝钉已出版书籍的原文，生成"随书解读课程"的课程图文稿。供 Claude Code 作为 skill 使用。

## 这个 skill 做什么

螺丝钉每出一本书，会配套制作一套"图书解读课程图文稿"（书籍精华内容，浓缩改写成口播文案）。这是一条两步交付的流水线：

1. **大纲**（飞书电子表格）——按章拆解全书要点，规划课程的节数与每节内容框架，交用户确认
2. **图文稿**（飞书文档）——大纲确认后，把每行"主要内容"逐条扩写成完整口播文案

已确认案例：《红利指数基金投资指南》（5节）、《个人养老金投资指南》（7节）、《固收+投资指南》（7节）。

## 为什么分两步、为什么不能跳步

图文稿不是重新读书独立创作的——它的节数、节标题、每节要覆盖的要点范围，全部来自 confirmed 大纲。写图文稿时只做"扩写"这一件事，不重新做取舍。大纲没确认不能写图文稿；图文稿没确认不能碰下游 PPT/音频等环节。

这个约束是踩过坑之后加的：跳过确认直接往后走，容易导致返工——大纲阶段砍掉的内容，图文稿阶段又给加回来；或者图文稿写完才发现大纲有遗漏，回头改大纲又要重新过一遍确认流程。

## 大纲怎么判断"哪些是重要内容"

不是"整段话是否精彩"，而是分三层过筛：

- **书本身自带的结构骨架**（"三个特点""四个分类"这类显性枚举）—— 全部保留，一条不能少
- **支撑框架的代表性例证**（具体指数名称、具体数字）—— 简单提及，不逐条展开
- **纯参考资料型内容**（完整产品对照表、历史数据明细）—— 大纲阶段直接不写，图文稿里留"如图所示"占位

## 配图规则：本 skill 完全被动

图文稿最终交付物是文档本身，不涉及 AI 配音、视频合成等下游环节。配图统一是"PPT 页面截图"的形式，但整体 PPT 排版、配图进度全部由用户自己把控——**本 skill 不主动检查配图进度、不主动匹配图片、不主动提醒该配图了**，只有用户明确 @ 提出某处需要新做可视化时才生成对应素材。

## 口语化复核：写初稿时就按习惯写，复核阶段查漏

图文稿写完（或用户调整后）要做一次口语化复核——逐节审读、标问题给建议，不直接改文档，等用户确认要改哪些再动手。

审读标准来自两条独立验证过的规律来源：

1. **对比 AI 初稿与钉大定稿**：编号小标题去生硬化、具体机构名能省则省、图表数据别逐句复述、参考资料型内容用"书里有"话术代替、抽象术语配生活化比喻等
2. **对比编辑（如李菁）批注前后**：开场预告句可以整体省略、讲完风险点加一句安抚性收尾、专业概念从上位概念切入再收窄、结论先行细节后置等

这两条规律现在都已经前置到"图文稿结构与规则"的文风转换规则里——写初稿时就直接按这些习惯写，不用等复核阶段才第一次应用。

## 文件结构

```
book-course-script/
├── SKILL.md      # skill 本体：大纲/图文稿结构规则、配图规则、口语化复核标准、自检清单
└── README.md
```

## 使用前提

- 装在 `~/.claude/skills/book-course-script/` 下即可被 Claude Code 识别
- 依赖 `lark-doc`（飞书文档读写）、`lark-drive`（复制文档、评论）等飞书技能完成大纲/图文稿的落地和交互

## 边界

不负责 PPT 整体制作、AI 配音生成、音画合成剪辑——这些在用户自己的流程里完成；本 skill 只负责大纲、图文稿正文，以及用户明确要求时的可视化素材生成。
